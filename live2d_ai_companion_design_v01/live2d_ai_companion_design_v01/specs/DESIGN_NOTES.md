# DESIGN_NOTES.md

## Product identity

The app should be understood as a persistent virtual character interface, not a chat client.

The user opens the app and immediately sees the character.

Character selection, logs, settings, and advanced capabilities are secondary.

## Why the main page avoids a chat waterfall

A traditional chat timeline makes text the dominant content.

Here the intended hierarchy is:

1. character
2. current response / expression / motion
3. user input
4. historical information

## Visual references

The concept direction uses:
- translucent floating layers
- cool blue-white palette
- restrained futuristic ornament
- anime character as full-screen subject
- minimal permanent chrome

The goal is the feeling, not imitation of any specific game UI.

## V0.1 interaction priority

The first 10 seconds matter most:

1. app opens
2. character is already visible
3. user initiates input
4. response appears
5. character enters speaking state

Polish this loop before expanding feature breadth.
